# 二分算法知识点总结

---

## 一、二分的两大前提（缺一不可）

| 前提 | 说明 | 怎么判断 |
|---|---|---|
| **① 有限区间** | 答案落在确定的 `[lo, hi]` 内 | 能说出答案的上下界 |
| **② 单调性** | 谓词 `check(x)` 随 `x` 增大只从「真」变「假」（或反之），不回头 | 一句话说清"x 可行，那更大/更小的 x 是否也可行" |

> **范围给二分划搜索空间，单调性保证砍掉的半边绝无答案。** 只有范围没有单调性，二分失效。

**单调性的标准形状：**
```
x:      小 ................................ 大
check:  真 真 真 真 真 | 假 假 假 假 假
                      ↑
                  分界点 = 答案
```

---

## 二、二分查找 vs 二分答案：同一模板

| | 二分查找 | 二分答案 |
|---|---|---|
| 搜索对象 | 有序数组 `a[]` 的下标 | 答案空间 `[lo, hi]` |
| `mid` 含义 | 数组下标 | 一个候选答案 |
| 判断方式 | `a[mid]` 与 target 比大小 | 调用 `check(mid)` |
| `check` 代价 | $O(1)$ | $O(N)$ 或更高 |
| 总复杂度 | $O(\log n)$ | $O(\log(\text{范围}) \times \text{check代价})$ |
| 单调性来源 | 数组有序 | 问题结构单调 |

**核心洞察：**
> **二分查找 = 二分答案的特例。** 二分查找的 `check(x)` 就是 `a[x] < target`。"数组有序"和"check 单调"本质是同一件事。

**统一形式：**
```
在 [lo, hi] 中找"最后一个使 check(x) 为真的 x"（或第一个使之为真的 x）
```

## 三、两套模板（必须成对记忆）

### 模板 A：找「最大可行值」（上界）

```cpp
int lo = 下界, hi = 上界;
while (lo < hi) {
    int mid = (lo + hi + 1) / 2;   // ★ 向上取整
    if (check(mid)) lo = mid;      // 可行 → 往大找
    else            hi = mid - 1;  // 不可行 → 往小找
}
// 答案 = lo
```

### 模板 B：找「最小可行值」（下界）

```cpp
int lo = 下界, hi = 上界;
while (lo < hi) {
    int mid = (lo + hi) / 2;       // ★ 向下取整
    if (check(mid)) hi = mid;      // 可行 → 往小找
    else            lo = mid + 1;  // 不可行 → 往大找
}
// 答案 = lo
```

### 配对口诀

| 边界更新 | 找什么 | `mid` 取整 | 原因 |
|---|---|---|---|
| `lo = mid; hi = mid - 1;` | 最大可行值 | **向上** `(lo+hi+1)/2` | 防 `lo=mid` 原地踏步 |
| `lo = mid + 1; hi = mid;` | 最小可行值 | **向下** `(lo+hi)/2` | 防 `hi=mid` 原地踏步 |

> **规律：哪个边界写成 `= mid`（不带 ±1），`mid` 就往那个边界方向偏。**

## 四、中点取整：为什么要 +1

### 死循环的根源

模板 A 中 `lo = mid`（不 +1）。若 `mid` 向下取整，当 `lo` 和 `hi` 相邻时：

```
lo=2, hi=3, mid=(2+3)/2=2
check(2) 真 → lo = mid = 2  ← lo 没变！
下一轮还是 mid=2，永远出不去 → 死循环
```

### 向上取整解决

```
lo=2, hi=3, mid=(2+3+1)/2=3
check(3) 真 → lo=3，lo==hi 结束 ✓
check(3) 假 → hi=2，lo==hi 结束 ✓
```

**结论：`+1` 保证每轮区间严格缩小，永不卡死。**

## 五、`check` 函数：二分的灵魂

### 设计要点

1. **`check(x)` 必须单调**：一旦为假，更大的 x 全为假（或反之）。
2. **`check` 的代价决定总复杂度**：$O(N\log L)$ 或 $O(N\log^2 L)$ 等。
3. **`check` 内部常用贪心**：但必须选对贪心策略。

### 贪心验证的正确性来源

P2678 中 `check(d)` 的贪心：**距离 < d 就删当前、≥ d 就留**。

**为什么这个贪心对？** 归纳证明「贪心保留的石头逐项最靠前」→ 保留最多 → 删得最少。

| 贪心类型 | 是否有硬约束 | 是否最优 |
|---|---|---|
| "合并最小段"（无阈值） | 无，纯凭数值 | ❌ 有反例 |
| `check(d)` 的删除（有阈值 d） | 有，不够就删 | ✓ 归纳可证 |

> **关键：有硬约束（阈值 d）时，删除是被迫的、选择唯一的，贪心不会短视。**

## 六、P2678 跳石头：完整案例

### 问题
长度 $L$ 的赛道上有 $N$ 块石头，最多移走 $M$ 块，**最大化**最短跳跃距离。

### 问题映射
| 二分要素 | 对应 |
|---|---|
| 搜索空间 | `[0, L]`（最短距离的范围） |
| `mid` | 候选最短距离 $d$ |
| `check(mid)` | 移走 ≤ M 块后，能否让所有相邻距离 ≥ mid |
| 单调性 | $d$ 越大越难满足，`check` 从真变假 |
| 模板 | 最大可行值（上界）→ `lo = mid; hi = mid - 1;` → 向上取整 |

### `check` 的贪心
```cpp
auto check = [&](int d) -> bool {
    int removed = 0, last = 0;             // last = 上一块保留石头的下标
    for (int i = 1; i <= N; ++i) {
        if (a[i] - a[last] < d) ++removed; // 太近，移走 a[i]
        else                    last = i;  // 够远，保留
    }
    if (L - a[last] < d) ++removed;        // 最后一段不够
    return removed <= M;
};
```

### 完整代码
```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int L, N, M;
    cin >> L >> N >> M;

    vector<int> a(N + 1);
    a[0] = 0;
    for (int i = 1; i <= N; ++i) cin >> a[i];

    auto check = [&](int d) -> bool {
        int removed = 0, last = 0;
        for (int i = 1; i <= N; ++i) {
            if (a[i] - a[last] < d) ++removed;
            else                    last = i;
        }
        if (L - a[last] < d) ++removed;
        return removed <= M;
    };

    int lo = 0, hi = L;
    while (lo < hi) {
        int mid = (lo + hi + 1) / 2;
        if (check(mid)) lo = mid;
        else            hi = mid - 1;
    }

    cout << lo << '\n';
    return 0;
}
```

### 复杂度
- `check`：$O(N)$
- 二分：$O(\log L)$
- 总计：$O(N\log L)$

## 七、常见陷阱速查

| 陷阱 | 后果 | 正确做法 |
|---|---|---|
| 取整方向与边界更新不配对 | **死循环** | `lo=mid` 配向上取整，`hi=mid` 配向下取整 |
| 没有单调性就用二分 | **答案错误** | 先用一句话验证单调性 |
| `check` 返回 `== M` 而非 `<= M` | 漏掉"预算有余"的情况 | 题目允许"至多 M 次"，用 `<=` |
| `lo = mid - 1` 但 `mid` 向上取整 | 可能跳过可行解 | 严格按模板配对 |
| 区间初始化错误 | 答案越界 | 下界取"一定不可行/最小可能"，上界取"一定可行/最大可能" |
| `mid = (lo + hi) / 2` 当 `lo + hi` 溢出 | UB（大范围） | 用 `lo + (hi - lo) / 2` |
| 贪心无硬约束却以为最优 | **WA**（如"合并最小段"） | 有硬约束才贪心；否则换其他方法 |
| `check` 中途返回但状态没重置 | 结果错误 | 每次 `check` 独立完整，或用 lambda 局部变量 |

## 八、二分答案的适用信号

出现以下关键词，优先考虑二分答案：

- "**最大值最小化**" / "**最小值最大化**"
- "**至少** / **至多** 移走 K 个，使...最优"
- "**能否**在预算内达成某目标"
- 答案**难以直接公式求解**，但**容易验证**某个候选是否可行
- 问题可抽象为"**存在一个单调的可行性判定**"

### 二分答案的思维流程

```
① 答案是什么？→ 确定搜索对象（如"最短距离"）
② 答案范围？→ 确定 [lo, hi]
③ 怎么验证一个候选 x 可行？→ 设计 check(x)
④ check 是否单调？→ 验证"x 可行则更大/更小也可行"
⑤ 找哪个极值？→ 选模板 A（最大可行）或 B（最小可行）
⑥ 选对取整方向 → 防死循环
```

## 九、核心知识点速记

| # | 知识点 | 一句话 |
|---|---|---|
| 1 | 二分前提 | 有限区间 + 单调性，缺一不可 |
| 2 | 二分查找 = 二分答案特例 | `check` 从"比大小"换成"可行性判断" |
| 3 | 两套模板 | `lo=mid` 配向上取整（找最大），`hi=mid` 配向下取整（找最小） |
| 4 | `+1` 的意义 | 防 `lo=mid` 死循环，保证区间每轮严格缩小 |
| 5 | `check` 是灵魂 | 单调性来自 `check`；`check` 代价决定总复杂度 |
| 6 | 贪心需硬约束 | 有阈值才贪心，无阈值贪心易错（反例可证） |
| 7 | `<= M` 不是 `== M` | "至多"预算，最少删除数 ≤ M 即可行 |
| 8 | 复杂度 | $O(\log(\text{范围}) \times \text{check代价})$ |
| 9 | 最大可行值 | 答案 = `lo`，循环结束时 `lo == hi` |
| 10 | 溢出 | 大范围用 `lo + (hi - lo) / 2` |

## 十、补充：二分答案 vs 其他算法

| 场景 | 推荐算法 | 原因 |
|---|---|---|
| 有序数组找元素 | 二分查找 | $O(\log n)$ |
| 最小化最大值 / 最大化最小值 | **二分答案 + check** | 答案难直接求，但可验证 |
| 无单调性的最优化 | 贪心 / DP / 三分（凸函数） | 二分前提不满足 |
| 求函数极值（非单调，单峰） | 三分法 | 二分不适用 |
| 答案空间巨大但可验证 | 二分答案 | 不受范围大小限制（$O(\log)$ 级） |

> **三分法**：函数先增后减（或先减后增）求极值时用，每次取 `m1 = l + (r-l)/3`、`m2 = r - (r-l)/3`，比较 `f(m1)` 与 `f(m2)` 缩区间——是二分在"单峰函数"上的推广。

---

## 十一、一句话总结

> **二分 = 在单调的有限区间里每次砍一半。二分查找砍数组，二分答案砍答案空间。两套模板按"最大可行/最小可行"选，取整方向和 `lo=mid`/`hi=mid` 严格配对防死循环，`check` 函数保证单调性和正确性。** 看到"最大值最小化/最小值最大化"，条件反射写二分答案。
